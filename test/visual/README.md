# Android pixel fixtures

This opt-in suite uses a complete app built by the production Ink CLI. Its path includes the compiler, SDK, actual QuickJS worker, Rust scene engine, JNI, Kotlin activity/adapters, local asset decoding and Android Vulkan rendering. It is separate from host scene descriptions and direct Kotlin adapter instrumentation.

There are six reviewable states and fourteen pixel-region checks:

| State | Regions and observable contract | Realistic regression |
| --- | --- | --- |
| `graphics` | Header; Canvas outline and primitives overflowing its right/bottom bounds; clipped Canvas text; accented text wrapping with a two-line limit; the same image in contain and cover modes. | Lost clipping, altered glyph/line placement, omitted ellipsis, incorrect texture fit/cropping or a missing image. |
| `list-start` | Fixed header and initial native list viewport, including rows, gaps and scrollbar. | Wrong initial window, changed row spacing or text placement, viewport leakage or a missing scrollbar. |
| `list-end` | Fixed header and final list viewport after actual touchscreen swipes. | Broken scrolling/window updates, header movement, wrong bottom clipping or scrollbar placement. |
| `rows-start` | Reverb-style wide album rows with unique generated artwork, one-line titles, subtitles and eight-unit gaps. | Missing artwork, incorrect image size, altered alignment or lost title truncation. |
| `rows-end` | Final album rows after scrolling through the artwork list. | Wrong artwork/text pairing, missing decoded images or incorrect bottom clipping. |
| `rows-return` | Initial album rows after scrolling away and returning. | Stale or missing artwork after native rows are recycled. |

The expected pixels require explicit human review. Capture never approves references.

## Prepare and review

Install this suite's isolated dependency once:

```sh
bun install --cwd test/visual --frozen-lockfile
emulator -avd Light_Phone_III -writable-system
bun test/visual/capture.ts --serial emulator-5554
```

Use the prescribed AVD, unmodified physical geometry `1080x1240` and density `480`. Set `JAVA_HOME` to JDK 17 or 21; on macOS the capture script locates JDK 17 when it is unset. The script sets `INK_SDK_ROOT` to this checkout and uses `cargo run --profile ink-dev -p ink-cli -- -C <fixture> build --debug`.

Before building, capture generates 32 distinct 256 × 256 greyscale covers using a fixed row-number seed, gradients, circles and a visible cover number. The generator follows the deleted scroll fixture's approach. Generated PNGs and their imports live in the fixture's ignored `.ink/` directory; the source and all generated bytes are included in the fixture hash. Re-running `bun test/visual/generate-artwork.ts` produces the same files. No downloaded artwork or committed image corpus is needed.

Each state must reach its production console-log marker and produce three consecutive identical decoded-RGBA captures within a bounded readiness wait. Each reviewed region must contain non-blank pixels, and consecutive states must differ. Delays pace polling and pointer input; they are not speed assertions. The manifest records geometry, device fingerprint, app source and APK hashes, full PNG/RGBA hashes, per-region hashes/colour counts, state meaning and exact input sequence.

Candidate images and build/device logs live under ignored `.test-output/visual/`. The capture script refuses to overwrite a candidate manifest, claims the same per-device lock as the Android harness, refuses an already-installed fixture package, installs only `com.vandam.ink.visualcontracts`, and uninstalls it and releases its lock in `finally`. It does not start or shut down emulators, clear logcat, alter display geometry or replace user apps. Process-group timeouts terminate spawned build/ADB descendants on this POSIX host.

### Inspection-tool diagnostic

During preparation, `view_image` incorrectly displayed the original `list-end.png` without its header. Direct decoding of the saved file showed the list-start/list-end header region had **zero changed pixels**, the same RGBA hash and 12,545 non-black pixels in each image. An encoding-only PNG copy displayed correctly while preserving every decoded RGBA byte. No rendering defect was inferred from the faulty preview.

If the viewer disagrees with saved-file evidence, create pixel-identical review copies:

```sh
bun test/visual/preview.ts --candidates <candidate-directory>
```

These are stored under `previews/`, with original/preview file hashes and their common decoded-RGBA hash. Original candidate files and approval metadata remain untouched. Pixel review uses the saved files; this suite does not use OCR.

## Explicit approval and comparison

After the user has reviewed and authorised the candidate states, record that approval:

```sh
bun test/visual/approve.ts --candidates <candidate-directory> --reviewed-by <reviewer> --approve
```

This copies the reviewed originals into `test/visual/references/` and pins their exact hashes plus the candidate manifest and fixture source hashes. References remain ignored until reviewed. Existing approvals cannot be silently replaced. Changing fixture source, region definitions, files, state set or the approved manifest invalidates approval.

Only after approval, run:

```sh
bun test/visual/run.ts --serial emulator-5554
# Or the shared opt-in runner:
bun run test visual --serial emulator-5554
```

The comparison runner refuses absent/invalid approval before building or touching a device. It recaptures the actual app and compares each approved region's decoded RGBA pixels. At most 0.1% of a region's pixels may differ, with every channel difference at most 16/255 and no alpha differences. This allows sparse text-edge shading variations seen in the reviewed captures. Any larger difference fails, including a single missing white pixel; widespread small shading changes also fail. Controlled one-pixel row movement, a missing row, widespread shading changes and altered opacity fail this rule. Counts and maximum differences remain in the evidence alongside the comparison tolerance. Its pass/fail totals count **fourteen regions**, not six screenshots.

This is deliberately a small fixture suite. It does not cover every widget, font, screen size, physical-device driver, colour scheme, keyboard, permission dialog or remote image; it does not infer performance from elapsed capture time.
