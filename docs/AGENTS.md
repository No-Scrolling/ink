# Documentation

Follow the [Cloudflare style guide](https://developers.cloudflare.com/style-guide/), using British English.

- Lead with what the feature does or the task the page explains.
- Give the action and expected result. Explain unfamiliar terms when first needed.
- Remove motivational copy, app idea lists and claims that something is easy.
- Delete routine narration such as “run the commands below”, “for example” and sentences that repeat a heading. Keep file paths, working directories and prerequisites when needed to use an example correctly.
- Keep one topic per paragraph. Use descriptive headings for separate API behaviours.
- Keep setup steps in the main flow. Put necessary failure guidance beside the relevant feature.
- Preserve defaults, limitations and error behaviour. Simplify their wording, not their meaning.
- Use sentence case for titles and headings. Preserve API names and actual UI labels.
- Label incomplete examples and state their prerequisites.

## Component pages

- Follow Buttons, Inputs and Reordering: concise code beside emulator screenshots from a focused preview app.
- Give useful variations their own sections. Use screenshot tabs for different states of the same example.
- Add code only when configuration changes. Let screenshots explain visible behaviour; omit redundant captions and instructions.
- Keep screenshots square-cornered. Use explicit `<p>` elements inside layout containers so paragraphs stay separate.
