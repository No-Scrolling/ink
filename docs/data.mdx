Use `resource` for data shared across screens. Use `useAction` for commands such as saving a setting or sending a message.

## Load data

Define a resource outside the component. `useSnapshot` loads its data and updates the screen when it changes.

`getForecast(placeId)` must return a promise with a `temperature` value. Import `@ink/network` in that module if it uses `fetch`.

<div className="pattern-example">
<div>

```tsx
import { resource, useSnapshot, Screen, Text, LoadingState, ErrorState } from "ink";
import { getForecast } from "../lib/api";

const forecast = resource({
  key: (placeId: string) => [placeId],
  load: getForecast,
  staleTime: 60_000,
});

export default function Forecast() {
  const source = forecast("london");
  const result = useSnapshot(source);

  if (result.status === "loading") {
    return <Screen title="Forecast"><LoadingState /></Screen>;
  }
  if (result.status === "error") {
    return <Screen title="Forecast">
      <ErrorState message={result.error.message} onRetry={source.refresh} />
    </Screen>;
  }
  return <Screen title="Forecast">
    <Text>{result.data.temperature}°</Text>
  </Screen>;
}
```

</div>

The key identifies the cached result. Include every value that changes the response, such as location and units. Keys contain strings, finite numbers, booleans or `null`. Each resource has its own cache.

## Refresh data

| Option | Behaviour |
| --- | --- |
| `staleTime` | How long data stays fresh, in milliseconds. Defaults to `0`. |
| `refreshInterval` | Reloads data periodically while a screen uses it. Omit to disable. |

Both intervals start after a successful load. Opening a screen with stale data starts a refresh and keeps the previous result visible.

Call `source.refresh()` to refresh immediately. It reuses any pending request and resolves when that request finishes. Read errors from the snapshot.

### Refresh errors

A failed refresh keeps the existing data and sets `refreshError`. Inside the loaded screen, offer a retry without replacing its content:

```tsx
{result.refreshError && <>
  <Text>{result.refreshError.message}</Text>
  <Button onPress={source.refresh}>Try again</Button>
</>}
```

Import `Button` from `ink`. `result.refreshing` indicates an active refresh. Failures stop periodic refreshes and delay automatic retries for one minute; `source.refresh()` bypasses that delay.

## Save and send actions

`useAction` tracks a command’s progress and catches errors. Call it inside a component, then pass `run` to the relevant handler.

This example uses a [Store](/store) named `preferences` with a `units` setting:

<div className="pattern-example">
<div>

```tsx
import { back, useAction, Screen, SettingsChoices, Text } from "ink";
import { preferences } from "../lib/preferences";

export default function Units({ value }: { value: string }) {
  const save = useAction(async (units: string) => {
    await preferences.update(current => ({ ...current, units }));
    back();
  });

  return <Screen title="Units">
    <SettingsChoices
      options={[
        { value: "metric", label: "Metric" },
        { value: "imperial", label: "Imperial" },
      ]}
      value={value}
      onChange={save.run}
      disabled={save.status === "pending"}
    />
    {save.status === "error" && <Text>{save.error.message}</Text>}
  </Screen>;
}
```

</div>
<div className="pattern-preview">
<img src="/images/patterns/action-units.png" alt="Metric and Imperial choices, with Metric selected." width="1080" height="1240" />
</div>
</div>

Pass the saved value to this component. Await the save before `back()` so the previous page shows the change when it returns.

An action’s status is `idle`, `pending`, `success` or `error`. Repeated calls while pending are ignored. Successful results are available as `data`; failures as `error`. Call `run` with the same arguments to retry. Keep inputs visible while saving, with errors underneath.

## Cache lifetime

Hidden screens stop using their resources. Periodic refreshes stop when no subscribers remain, but pending requests finish. Unused data expires after five minutes, counted from the end of any pending request.

The cache clears when the app restarts. Use [Store](/store) for data that must persist.

Putting the app in the background does not unsubscribe its screen. Use [Background work](/background) for scheduled jobs; resource refreshes do not guarantee background execution.

## Keep input responsive during computation

Split CPU-heavy JavaScript work into small chunks and await `yieldToInput()` between them. This lets Ink process pending input before the next chunk. Choose a chunk size that finishes within your interaction budget on the target device.

This function expects a synchronous `processRecord` callback:

```ts
import { yieldToInput } from "ink";

async function processRecords<T>(
  records: readonly T[],
  processRecord: (record: T) => void,
  signal?: AbortSignal,
) {
  for (let start = 0; start < records.length; start += 128) {
    signal?.throwIfAborted();
    const end = Math.min(records.length, start + 128);
    for (let index = start; index < end; index++) processRecord(records[index]);
    await yieldToInput(signal);
  }
}
```

An aborted signal rejects the pending yield with its reason. Yielding adds scheduling overhead and does not interrupt a running chunk. This API runs while the app is active; use [Background work](/background) for jobs that must run after it closes.

## Update keyed records

Use `createSource` for a large collection that receives small changes. Ink stores the records natively and maintains equality-filtered views as records change. This is an in-memory collection; use [Store](/store) for persistence.

Ordinary [`List`](/lists) components already apply native storage and cooperative row preparation automatically where eligible. A source is optional: use it when the application can provide keyed changes directly and needs native filtered views instead of rebuilding JavaScript arrays.

```ts
import { createSource } from "ink";

type Message = { id: string; title: string; preview: string; read: boolean };
const messages = createSource<Message>([
  { id: "m1", title: "Alex", preview: "See you tomorrow", read: false },
], { key: "id" });
const unread = messages.view({ read: false });

const before = messages.getSnapshot();
messages.set({ ...before.get("m1")!, read: true });
unread.getSnapshot().count; // 0
before.get("m1")!.read; // false: snapshots retain their original values
```

Keys must be unique, non-empty strings. Records must contain plain JSON data: finite numbers, strings, booleans, `null`, arrays and plain objects. Snapshot records are frozen. `get(key)` and `at(index)` return `undefined` when no record matches. `useSnapshot(source)` subscribes a React component and returns the same snapshot until that view changes.

`view({ read: false })` matches top-level fields by primitive equality. Multiple fields must all match; a missing field differs from `null`. Views retain source order. Arbitrary predicates, sorting, joins and nested-field filters are not supported.

### Change several records together

`transact` replaces existing records atomically. Pass the revision you read to reject a stale update. Duplicate or unknown keys and invalid data reject the whole transaction without changing the collection. `set` replaces one existing record using the current revision.

```ts
const snapshot = messages.getSnapshot();
messages.transact([
  { ...snapshot.get("m1")!, preview: "Updated preview" },
], snapshot.revision);
```

Use `replace(records, revision?)` to replace the entire collection, including insertions, removals or a new order. This scans the collection. Identical values do not advance revisions or notify subscribers. Small stable-key changes update the relevant records and view membership; binding a filtered list whose membership changes can still rebuild its key order.

### Bind native rows

`SourceList` takes a source or view and record field names for `title`, optional `subtitle` and optional `image`. Each selected field must contain a string. It uses standard Ink rows, with `titleMaxLines={2}` and `gap={47}` by default. `onPress(key)` and `onLongPress(key)` identify the current record by key. Use `List` when rows need arbitrary React content or pagination callbacks.

Inside a screen, a source list can use `view={messages}`, `title="title"` and `subtitle="preview"`. Read `messages.getSnapshot().get(key)` in the press handler to get the current record. Changing bound field names remounts the native list.

### Release a collection

Call `view.dispose()` when a derived view is no longer needed. Call `source.dispose()` when its owner finishes with the collection; this releases all its views. Unmount source lists first. Already returned snapshots remain readable, but disposed sources and views reject new reads, mutations and subscriptions. A list that remains mounted retains its last snapshot.

A runtime supports 64 sources, 256 views including base sources, and one million current records across sources. Each record can encode at most 1 MiB, and current records can encode at most 256 MiB in total. These limits exclude allocation overhead and retained snapshots. Transport failure stops further source delivery and requires a runtime reload.
