# Fresh independent general audit — 29 September 2026

## Result and scope

The final reviewed application tree has no outstanding defect established by this audit. Two defects were independently discovered during the broad investigation, reported immediately and subsequently corrected by the source owner. A further callable-property case was supplied as a follow-up trigger after that report; this reviewer independently reproduced its compiler/eligibility/snapshot mechanism and validated the subsequent correction, without reading another reviewer’s report. The bound-list correction was reproduced against the current code with the same observational executable and its explicit empty-patch control. The network expiry correction was revalidated by tracing the current scheduler, every call site, handle ownership and shutdown. Its original defect was a source-level scheduling proof, not an Android wall-clock experiment.

This result is deliberately narrower than a claim that Ink is defect-free. The audit followed contracts from public TypeScript APIs through compilation, QuickJS, typed protocol transport, Rust tree/layout and the Android bridge/adapters. It inspected the current tracked modifications and relevant untracked implementation, rather than reviewing only the Git diff. Hardware behaviour, rendered pixels, Android lifecycle timing and every possible capability combination were not all exercised. The exact coverage and omissions appear below.

No application source or repository tests were written or modified by this audit. The only diagnostic programme added is a standalone observational executable inside this evidence directory. Existing tests, existing headless fixtures and isolated Android builds were used. No device was reserved, installed, changed or operated; no claim about visual defects, measured device memory or phone latency is made.

## Established defects, corrected during the audit

### A. Bound native-list option updates originally stopped the application runtime

**Original trigger.** Mount a native bound view containing a non-empty `view.list` whose `hasMore` is a Boolean binding, then change only that binding. The equivalent `hasOlder` route also reaches the same metadata branch. This is a supported public operation; it does not require malformed row data or an invalid template.

**Trace.** `packages/ink/src/view.ts` emits the scope's dirty values separately from collection patches. `crates/ink-core/src/react/view.rs` updates the bound target's complete host-prop snapshot and emits a native-list update. The host snapshot no longer includes initial `items`, `template`, `itemChanges` or `itemKeys`. The original existing-list branch in `crates/ink-core/src/react/native_list.rs` required an `itemChanges` array even when the only change was an option. It therefore returned `NativeList requires itemChanges`. `ScriptRuntime::apply_commit` in `platform/android/native/src/javascript.rs:112` propagates the error through draining; the JNI drain error path records the JavaScript error and discards the script. The consequence was a stopped application runtime, rather than merely a missing list update.

**Falsifying control.** A cloned tree with an explicit empty `itemChanges: []` and identical false `hasMore` completed successfully. The clone was created before the failing apply, because the original failure removes the existing list while expanding operations; a control on that already-mutated tree would have been invalid. The initial boundary callback showed the mounted list was live.

**Original evidence.** `bound-list-option-observation.log` records successful mounting, the initial `onEndReached` event, the failing values-only update and successful explicit-empty-patch control. `observations/src/main.rs` and its manifest retain the exact diagnostic.

**Smallest robust correction and current status.** Missing `itemChanges` represents an empty patch for an already mounted list, while a supplied non-array patch remains an error. Current `crates/ink-core/src/react/native_list.rs:170–173` implements this. Existing keys, items, template and mounted rows are retained; lines 200–205 update the options. Row version invalidation remains conditional on actual changed rows at lines 183–198. `bound-list-option-current.log` records the same values-only operation returning `Ok(())`, with the control still passing. The fresh current controls workload also passes. **Resolved and observationally revalidated.**

### B. Opening subsequent network transfers originally postponed abandoned-handle expiry indefinitely

**Original supported trigger.** Retain one abandoned response stream or upload, then successfully open and consume/cancel/close another response or upload more often than once per 60 seconds. Each successful open reset the single global sweep to 60 seconds from that open. The abandoned handle never had its idle age examined while this traffic continued.

**Important precision.** The original `scheduleExpiry` call sites were upload-open, successful stream-open and the sweep's own reschedule. Ordinary response reads and upload writes refreshed the relevant idle marker; they did **not** themselves call the original scheduler. The initial investigation's broader wording about reads/writes resetting the timer was corrected before finalisation. The proof uses repeated successful open/close traffic.

**Limits and controls.** The 16-response and 8-upload caps do not prevent the trigger: closing each new busy transfer frees its slot while preserving the single abandoned handle. If abandoned handles accumulate to a cap, rejected opens cease postponing the timer and expiry can eventually recover. Under quiet traffic the original sweep ran after 60 seconds and removed sufficiently old resources. Thus the issue was the starvation of the sweep by valid ongoing traffic, not failure of all expiry or a claim of unbounded handle counts.

**Evidence limit.** The original scheduler body and its call sites were inspected directly and recorded during the investigation; no dedicated before-change Kotlin file snapshot or Android timer trace was saved. The proof and exact supported trigger above are retained as source observations, with the current file hash in final provenance. This is weaker provenance than the executable evidence for finding A.

**Consequence.** Response requests/input streams and upload temporary files remained retained for an indefinitely long active session despite the documented inactivity expiry. Accumulated abandoned handles could also make later transfers fail with the finite handle cap. `docs/network.md` describes inactivity expiry after 60 seconds without reads/writes.

**Smallest robust correction and current status.** Preserve an already scheduled sweep; schedule the next check from the earliest retained handle's idle deadline and use a monotonic clock. Current `platform/android/app/src/network/kotlin/com/vandam/ink/InkFetchStreams.kt:211–226` does this with `expiryScheduled`, uptime, earliest touched time, inclusive idle comparison and rescheduling after each sweep. New opens cannot displace the pending callback. Completed upload work refreshes touched and schedules at lines 128–131; in-flight copying uploads are omitted from eviction; shutdown removes the callback and clears the scheduled flag at lines 201–209. **Resolved by current source tracing; Android timed execution remains unmeasured.**

### C. Follow-up validation: captured callables with own fields bypassed eligibility and snapshot checks

**Trigger and source provenance.** The owner supplied the concrete trigger after the broad audit: an ordinary captured callable has a `label` getter or a mutable own `label` data property, read by compiler-eligible JSX such as `<Text>{named.label}</Text>`. This was not independently discovered in the original broad pass. It was independently reconstructed and observed here from the exact before-change source snapshot `native-list-before-callable.ts` (SHA-256 `fc74e41c8b8e218db5b5f84afc911d1552a46a0c57327e8429d426e318bfe615`) and the current compiler implementation.

**Trace and consequence.** `crates/ink-compiler/src/native-lists.js:27` accepts property access when its base expression is eligible; lines 43–48 capture the base callable, and line 113 emits the scope capture. The original `plainData` returned true immediately for an ordinary function, without inspecting its own descriptors. The original `captureValue` also stored functions as identity-only leaves. The observed getter was accepted for native projection, and a changed own `label` still compared as an unchanged captured scope. With retained item/key/template identity, `CompiledList` then reused previous projected records, so the field could remain stale. Accessor-backed labels also bypassed the intended React fallback for executable property reads. This is a compiler/runtime eligibility and memoisation issue; no visual defect is asserted.

**Observational evidence and controls.** `callable-observation.ts` extracts the actual eligibility and snapshot helpers from either saved or current source, uses the actual compiler transformer for the JSX example, and creates ordinary arrow/normal functions. For these freshly constructed non-Proxy functions only, it models the runtime predicate as `__inkIsProxy = () => false`. This is a narrow host-side source observation, not a full QuickJS/React scene reproduction. `callable-observation-before.log` shows the compiler transforms and captures the callable, getter eligibility is true, and an own data-property change appears unchanged. `callable-observation-current.log` shows getter eligibility false without invoking the getter during validation, the data-property change compares unequal, and ordinary callbacks plus ordinary functions remain eligible and stable. A custom prototype with a constructor cycle is rejected for fallback; nested callable data stays eligible. Getter projection is read separately only to demonstrate that the field itself remains an executable read; this is not part of eligibility validation.

**Smallest robust correction and current status.** Validate function descriptors/plain fields and snapshot function fields under the same rules as other captured data. Preserve the intrinsic bare function prototype back-reference as a narrowly checked identity leaf, without exempting custom prototype graphs. Current `packages/ink/src/native-list.ts:26–45` validates callables and rejects accessors; lines 108–120 snapshot their own fields; line 125 prevents an unverified host from claiming unchanged callable captures. Lines 19–23 exempt only a non-Proxy object with `Object.prototype` and a sole own data `constructor` back-reference to its owner. Current source SHA-256 is `cc5428e711d9babe719b95e051de3d907d9093ede247183e3da76149449e0d00`. The final local-variable rename was reread and included in provenance. The existing list fixture passes its controls after the behavioural correction (`headless-20260929-214432-6c8220ea`), and the current TypeScript compile passes. **Resolved by independent source/helper observations and existing-fixture validation; the exact callable-trigger scene was not exercised in QuickJS by this reviewer.**

## Contracts reconstructed and coverage

### SDK, compiler and protocol boundary

The main UI exports are host descriptions; React owns component state and callbacks while the Rust engine owns layout, scrolling and materialised native rows. `renderer.ts` maintains mounted instances, normalises native props and batches text/structural updates. Functions cross as Boolean event capabilities; actual callbacks remain in JavaScript. Bound views use separately allocated values, declarative derived expressions, subscriptions and collection revisions. Their updates bypass React reconciliation after mount.

The compiler's native-list transformation was reviewed with import-symbol/shadowing checks, eligible host descriptions, key-field extraction, capture identity, pure projections, unsupported-expression fallback and event dispatch. The existing eligibility suite exercises native Text/Row, JSX entities, import aliases and shadowing, mutation/ref/spread/custom-component fallback. Current `packages/ink/src/native-list.ts` was reread after the final owner edits: QuickJS's `__inkIsProxy` provides side-effect-free proxy detection; absent that predicate, captured objects cannot establish a reusable unchanged capture. Row text normalisation follows primitive React text semantics, projected fields are separate from callback execution, and callbacks are recalculated from current row records when dispatched. Immutable item identity is part of the memoisation contract; this audit does not infer correctness for applications mutating immutable list records in place.

The Rust commit boundary checks operation names, safe non-negative JavaScript identifiers, binding identifiers, text batch parity and message size. Nested bound-view node identity and references are checked before host insertion. Current `commit.rs`, `native_list.rs`, `view.rs` and related protocol definitions were reread after boundary changes. Native row IDs occupy the reserved high native range; events are routed to the safe JavaScript list/template target before JavaScript receives them. Binary messages have separate copying, identity, size, count and ownership rules. The outgoing sidecar is consumed once, and duplicate/rejected payloads do not replace stored bytes.

Bundle assembly was traced through native declarations/capabilities, split-web lazy modules, hashed file/database assets, icon usage and development rebuild handling. Catalogue-driven Rust features, Kotlin enabled/disabled source groups, generated permissions/components and worker packaging were inspected. Minimal core features were compiled. The isolated builds check selected real configurations, not the combinatorial power set of the catalogue. CLI create/build/development/watch and quality entry points received source coverage; formatting and dependency installation were not invoked on the live application tree.

### Runtime, cancellation and ownership

The QuickJS worker has explicit heap/stack limits, bounded event queues and byte budgets. Coalesced latest-state messages differ from terminal results. Message budget ownership follows queue entries through acceptance, replacement and removal. Promise work is drained in batches; cancellation and interruption are distinct from arbitrary I/O rollback. `AppRuntime` stop wakes the worker and joins it; retained binary buffers live with the runtime.

The SDK removes aborted pending calls, rejects them and posts cancellation; late results no longer have a JavaScript pending owner. Android `NativeRequests` tracks each pending request object, timer and cancellation hook, removes ownership before completion and disposes unclaimed resource-bearing success results. Source tracing checked timeout, completion, cancellation and session-close paths. Controller attachment readiness and disposal maintain event ownership, including cleanup when activation completes after React has left. Worker runtime handles are bounded, native stop removes the shared handle, and in-flight readers retain the runtime only for their bounded receive interval.

The Activity session transition was followed through script disposal, native-request closure, controller/adaptor reset, stale delivery checks and engine reset. UI scheduling guards prevent old-session JavaScript results from being delivered as current ones. Resource/migration/action hooks were inspected for pending identity, subscription lifetime, polling/backoff and unmounted completion. No extra fault was established from these paths. This source proof does not establish latency under an Android UI-thread stall or a hung external Binder service.

### Native lists, bound collections, input and layout

Complete and sparse native-list updates were traced through keys/indices/items, keyed row reuse, event mapping, deletion, template restrictions, host snapshot updates and list measurement invalidation. Width-dependent height caches and Fenwick offsets retain keyed identity; anchor restoration follows the retained visible key across reorder/prepend. Finite bounds prevent unlimited template depth/size and list-patch count.

Bound collections reserve asynchronous replacement ownership, reject stale revisions, stage native-query replacement before publication and propagate selection/derived expressions through their declared dependency order. Declarative expressions validate finite arithmetic, missing selection paths, bounded depth/parts and padding limits. Text length deliberately counts UTF-16 units.

Controlled input acknowledgement counts, recycling, state cleanup, cursor byte/UTF-16 conversions, numeric/control filtering and the Android native-editor overlay were traced. Existing headless controls exercise Unicode edits across recycling and monotonic acknowledgements. Layout coverage includes text/stack/row/avatar composite geometry, lists, route visibility, portals, canvas and text-width/font selection. No saved rendered screenshot was created and no visual defect is asserted; scene/text assertions establish CPU scene behaviour only. Japanese fallback, Arabic shaping, emoji atlas rasterisation, OEM keyboard composition and screenshot appearance remain device/rendering validation paths.

### Network, files and storage

Fetch body ownership was followed through immutable copied Blob bytes, native managed-file slices, multipart native-file upload parts, upload handles, response ReadableStream reads, reader cancellation and final stream close. Redirect credential removal, bounded buffered bodies, HTTP method/header restrictions and scoped camera-file URLs were inspected. WebSockets impose socket/frame/buffer bounds, finite read heartbeats and explicit reset/close. Downloads use persistent keyed jobs, stopped-generation state, partial files, validated range/validators, rename/adopt publication and cleanup on cancellation/failure. No downloaded or managed user data was touched.

Store writes use revision comparison and transactionally publish a committed result. The current final `StoreAdapter.kt` and `NativeAdapter.kt` were reread: write admission computes the escaped result envelope with the widest future revision and maximum safe request ID, protecting subsequent reads from crossing the native message limit. Metadata-only reads avoid loading the stored value during revision checks. Cancellation does not promise rollback of an already committed database write; this is not presented as an ownership leak.

Read-only bundled SQLite validates assets, copies to a partial/rename path, bounds result rows/envelope and uses cancellable queries. Query-to-bound-collection publication is staged and generation checked. Managed files validate canonical roots and identifiers, atomically publish metadata and bound decoding. Pick/save/share/import/media-library thumbnail flows were traced through cancellation and late-resource disposal. Permission variants, keyset media pagination and de-duplication were inspected.

The untracked wallet package and `InkPassFiles.kt` were included: archive/source limits, entry/artwork limits, sanitised fields/links, source cache keys, bounded pass caches, copied retained artwork ownership and release paths. Unsigned wallet fixture generation was inspected, but wallet rendering and scans were not operated. The untracked avatar asset, row/view/expression/queue modules and standalone audio-startup package were included in source provenance. The startup probe is separate experimental code with reservation checks, retained PCM allocations and endpoint timestamp estimates; no probe was run or acoustic claim inferred from it.

### Android adapters, services and renderer

Audio analyser capture uses a current-session token, a single latest sample and bounded DSP controller state; generation checks reject old DSP updates after changes. Recorder publication follows partial-file finalisation and managed-file adoption. Attached and detached playback lifecycle coverage includes session/controller ownership, future release, queued actions, queue persistence, progress timers, focus transitions and service idle stop. DSP arithmetic, renderer-factory/audio-effects/processor implementations received targeted source coverage, not a full audio-quality analysis.

Camera/scanner coverage follows session identity, asynchronous provider readiness, active/paused/deactivated ownership, staged photo save, stale attempt deletion and managed adoption. Scanner buffers honour row/pixel strides and close ImageProxy ownership on normal/error paths. Raw NFC connections have generation checks, cancellable pending calls and asynchronous close; NDEF/APDU flows have bounded payloads, finite reply deadlines and pause cleanup. Location current requests own CancellationSignals; foreground watches own listener and heartbeat removal; detached tracking is explicitly a service with visibility/notification prerequisites. Notifications and background jobs were traced through bounded persisted records, identities, generation checks, pinned worker bundles, retry/cancel and service destruction. Maps/video source coverage includes portal attachment, native-view lifecycle, session close, asynchronous readiness, release and UI callback guards. LightOS Binder, permissions, secure values, crypto and push paths received source ownership/validation coverage; external services were not contacted.

Renderer lifetime review followed the previous-frame wait before resource mutation, Android native-window/surface ownership, Vulkan core ownership, partial-construction guards, Surface idle wait on destruction and retained staging/texture resources through submission. Image request generations and decoder cancellation bound stale-result publication. System-glyph pages retain only current-scene keys, discard pending uploads before dropping unused pages, remap atlas references and enforce a finite page limit. This audit did not run GPU fault injection, process-death recovery, device-loss tests or a long animation/cache churn soak.

## Source provenance, independence and limitations

`source-provenance.json` records HEAD, SHA-256 and size for every current tracked/non-ignored untracked repository file outside generated evidence/build/dependency prefixes. `source-provenance.py` is the reusable collector. `current-status.txt` records the final tree status. The owner changed application source during this audit; the failure evidence is historical to the initial current tree, while the post-correction diagnostics, final source rereads and final hashes describe the later frozen tree. The final three updated files (`native-list.ts`, `StoreAdapter.kt`, `NativeAdapter.kt`) were reread independently. The last graph-sharing edit in `native-list.ts` was also reread and checked with the final exact live-source list headless run and TypeScript compile. The Android build snapshots precede that last TypeScript-only edit; their own source manifests identify the precise built inputs. The broad audit’s two original final hash captures agreed at `cc9a95bbbb0b271636cf698d0553df5fde920695c2e5ebb7878f00ddfc458c95`. Following callable-property validation and its final cleanup, the updated combined SHA-256 is `fb1ce545387108220b7475ad69ca2efb724be6ba07d111580d79fb18e4c5adda` over 1,146 included files. `source-provenance.json` describes that latest reviewed tree; earlier operation manifests retain their exact earlier inputs. No conclusion is taken from the parent's reports.

Previous generated audits, benchmark reports under `benchmarks/results`, and old `.agent-tools` outputs were excluded as review input. The repository's `docs/runtime-ownership.md` was inadvertently opened during broad documentation discovery before its retrospective content was recognised; its conclusions were not adopted or used to generate findings. The factual audit input is current implementation, public contracts, existing test/fixture source and this audit's own observations. Agent-tools isolated snapshots may retain repository files as build provenance; retained unrelated evidence was not read as review material.

The investigation was broad, with end-to-end traces in the highest-risk shared boundaries and ownership paths. It was not a line-by-line proof of every third-party dependency, every untouched utility, all player effect DSP, every installer/CLI edge or all push-server states. Those paths have targeted/source/build coverage as described, with third-party internals and their external contracts not independently verified. Visual findings require saved-pixel comparison and OCR under AGENTS.md; no such findings are reported. No Android idle-expiry timing, permission picker interaction, physical NFC/camera/audio/location, resource memory soak or kernel/GPU fault behaviour was measured. Those are unmeasured verification opportunities, not additional suspected bugs.
